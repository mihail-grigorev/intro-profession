## Моя рефлексия

Большинство тем занятия я уже знал, потому что давно пользуюсь Git и похожими инструментами, поэтому принципиально нового было немного. Лучше всего у меня получилась работа с Git: создание веток, коммиты и слияние через pull request. Больше всего трудностей вызвал GitVerse: при создании виртуального окружения возникала ошибка, я создавал новые аккаунты и репозитории, а техподдержка не смогла помочь, поэтому в итоге я выполнил задание на GitHub и в Codespaces.

В main (master) лежит основная рабочая версия проекта, а в отдельной ветке можно пробовать изменения и не сломать её, после проверки ветку вливают в основную. Commit фиксирует состояние проекта в истории, поэтому можно вернуться к рабочей версии, а понятные сообщения показывают, как менялся код. Виртуальное окружение .venv изолирует библиотеки проекта от остальных, и ноутбук должен использовать именно это ядро. Файл .env хранит секретные данные, например API-ключ, и благодаря .gitignore не попадает в коммит, иначе ключом мог бы воспользоваться любой посетитель публичного репозитория. JSON это текстовый формат данных в виде пар «ключ: значение», его разбирают, чтобы превратить ответ сервиса в объект Python и достать только нужные поля.

Из визуальных инструментов мне помогла панель Source Control, где видны изменённые файлы и можно делать commit и push, а ячейки ноутбука позволили запускать и проверять код по частям. AI-ассистент может сделать ревью кода, объяснить ошибку и предложить улучшения, например проверку ответа сервиса, но его советы нужно проверять самому. Для ревью я использовал ИИ-ассистента (не GigaCode) и проверил правки на существующем фильме, несуществующем названии и неверном ключе. Если бы я делал задание ещё раз, то сразу создал бы .gitignore, раньше активировал ключ и делал бы больше небольших коммитов.
